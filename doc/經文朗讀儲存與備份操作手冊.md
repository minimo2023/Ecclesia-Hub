# 經文朗讀儲存與備份操作手冊

## 儲存責任

- 生產主機專案資料夾是正式資料來源。
- 錄音存放在 `private-media/scripture-recordings/`，不在公開網站目錄內。
- PostgreSQL 保存錄音、分享、留言、回應、檢舉與審核資料。
- 網站執行期間不連線 NAS，也不保存 NAS 帳號或密碼。
- ProjectGuardian 負責將整個生產專案資料夾備份到 NAS；必須包含 `private-media/` 與 `backups/`。

## 每日資料庫備份

從專案根目錄執行：

```powershell
npm run backup:scripture-recordings
```

成功時會建立：

- `backups/postgres/daily/*.dump`：PostgreSQL 完整備份。
- `backups/manifests/daily/*.json`：音檔路徑、大小與 SHA-256 清單。
- `backups/manifests/last-success.json`：最近一次成功時間與檔案位置。

每日備份保留 7 份；星期日另建立每週備份並保留 4 份。任一音檔缺失、大小不符或雜湊不符時，該次工作會失敗，不會留下看似成功的結果。

## 安裝每日 03:30 排程

以有權建立 Windows 排程工作的帳號執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\platform\install-scripture-recording-backup-task.ps1
```

預設工作名稱為 `EcclesiaHub-ScriptureRecordingBackup`。安裝後應在 Windows 工作排程器手動執行一次，確認 `last-success.json` 的時間更新。

## 還原演練

從專案根目錄執行：

```powershell
npm run verify:scripture-recording-restore
```

驗證程式會：

1. 驗證資料庫 dump 的 SHA-256。
2. 驗證 manifest 所列音檔的大小與 SHA-256。
3. 建立臨時 PostgreSQL 資料庫。
4. 完整還原 dump 並核對 READY 音檔數量。
5. 刪除臨時資料庫，不改動生產資料。

至少每月執行一次，並保留成功輸出作為演練紀錄。

## ProjectGuardian 驗收

ProjectGuardian 的來源應設定為整個生產專案資料夾，而不是只選程式碼或 `private-media`。第一次設定及每次調整排除規則後，應進行以下人工驗收：

1. 在 `private-media/scripture-recordings/backup-test/` 放入一個測試檔案。
2. 執行 `npm run backup:scripture-recordings` 產生 dump 與 manifest。
3. 等待 ProjectGuardian 顯示備份成功。
4. 從 NAS 還原到新的臨時資料夾。
5. 確認測試檔、最新 dump、manifest 與 `last-success.json` 都存在。
6. 在還原副本執行雜湊核對；完成後只刪除自行建立的測試檔與臨時還原資料夾。

ProjectGuardian 沒有提供網站可讀取的狀態介面，因此網站不能可靠判斷「NAS 備份已成功」。管理者應以 ProjectGuardian 自身的最近成功時間與錯誤紀錄為準；超過 24 小時未成功時必須人工處理。

## 故障處理原則

- 網站可正常運作但 NAS 暫時離線：繼續使用生產主機本機資料，修復 ProjectGuardian，不修改網站儲存位置。
- dump 失敗：先保留既有成功備份，不手動偽造 `last-success.json`。
- manifest 發現缺檔或雜湊不符：先停止清理工作，從最近一次可信備份還原到臨時位置比對。
- 刪除錄音：先撤銷資料庫權限與分享，再由清理工作刪除實體檔；災難備份中的副本依備份輪替最多保留 30 天。
