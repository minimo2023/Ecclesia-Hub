# Ecclesia Hub 經文與社群功能分階段整合計畫

版本：2026-08-24

## 一、產品界線

本計畫不恢復已取消的「經文學習／AI 導師」模組，也不仿製 VerseRain 的整套產品。

固定界線：

- 經文區負責閱讀、搜尋、朗讀、個人紀錄、分享與共讀。
- 遊戲區維持問答、遠征、連線與排行榜，不把種植、挑戰、倍率或遊戲積分搬進讀經頁。
- 靈修筆記仍屬每日靈修；經文筆記屬使用者自由閱讀，兩者共用帳號與儲存基礎，但資料與畫面保持分開。
- 社群不以公開動態牆或陌生人互動起步，而以「把一段經文安全地交給已知的人」為第一目標。
- 附近教會屬真人轉介，不是社群評分、推薦或遊戲功能。

## 二、目前生產環境的真實能力

### 已有且可沿用

| 能力 | 現況 | 後續用途 |
|---|---|---|
| 正式經文庫 | 生產庫有 156,477 筆經文，主要包含 5 個完整繁中版本 | 閱讀、搜尋、分享與朗讀的唯一正文來源 |
| 經文讀取 | `GET /api/content/scripture` | 維持現有桌機與手機讀經頁 |
| 譯本與讀經計畫 | `/api/bible/versions`、讀經計畫 API | 沿用譯本選單、進度與完成紀錄 |
| 經文對照 | 桌機讀經頁已有「開啟對照」 | 保留，不另做新研究模組 |
| 經文劃線／筆記路由 | `/api/scripture-selections` | 修正後作為個人經文紀錄基礎 |
| 帳號與權限 | 現有 Auth／會員所有權驗證 | 私人筆記、共讀群組與分享管理 |
| 靈修與靈修筆記 | 已有完整獨立流程 | 不與自由讀經筆記混表或混畫面 |
| 地理資料 | `/api/content/geography/*` 與現有聖經地圖 | 只用於聖經地理，不作玩家位置地圖 |
| 回饋入口 | `/api/feedback` | 可沿用於功能回報，不等同社群檢舉系統 |

### 看似存在、但尚不能視為完成功能

- 生產庫的 `scripture_selections` 目前為 0 筆。
- 路由會寫入 `offset_start`、`offset_end` 並更新 `updated_at`，但生產資料表缺少這三個欄位；直接啟用可能失敗。
- 現有表也沒有 `version`，無法可靠區分同一經節在不同譯本下的劃線與筆記。
- 目前讀經介面沒有真正把劃線、筆記、書籤呈現給使用者。
- 頁首雖有通知圖示，但沒有可供一般社群通知沿用的完整資料表與 API。
- 現有搜尋是 AI／資料庫資源搜尋，不是單純、零 AI 成本的經文全文搜尋。
- 現有遊戲音效與題目朗讀不能直接視為讀經朗讀功能。
- 專案中尚未看到華人教會機構名錄 API 的後端整合器或正式設定名稱。

## 三、朗讀的技術選擇

第一版使用瀏覽器與裝置的 Web Speech Synthesis：

- 不需要申請 API。
- 不使用 AI 金鑰、不產生雲端費用。
- 經文不需傳送給第三方。
- 可提供播放／暫停／停止、上一節／下一節、語速及可用中文語音選擇。
- 朗讀時只標示目前節數，不做逐字同步，避免各裝置事件差異造成錯位。

限制：不同 Windows、Android、iOS 裝置的可用聲音與發音品質不同。若未來要求所有平台固定同一個台灣中文聲音、可下載音檔或精準逐字高亮，才另案評估雲端 TTS；不列入第一版。

## 四、UI／UX 方案

### 桌機

保留目前「經文探索 → 選書卷 → 選章 → 選譯本 → 經文」結構，只在章節標題下增加一列輕量工具：

`朗讀　錄下我的朗讀　搜尋　我的記錄　分享`

- 點擊單節或拖選連續經節後，右側開啟小型操作面板。
- 面板只顯示：劃線、筆記、書籤、複製、分享。
- 經文仍是畫面主體；不加入聊天框、遊戲卡片或公開貼文串。
- 朗讀時在頁面底部顯示窄型播放器，不覆蓋章節切換。

### 手機

保留底部導覽中的「聖經」。

- 點選經節後由底部抽屜呈現相同操作。
- 朗讀控制使用可收合的迷你播放器，位於底部導覽上方。
- 錄音控制使用獨立底部面板，清楚顯示錄音時間、停止、試聽、重錄、儲存與分享；不和系統朗讀按鈕混在一起。
- 「我的記錄」放在聖經頁內的次要入口，不再新增一個首頁大型功能卡。
- 分享使用系統原生分享；不支援時退回複製連結。

### 防止變成「四不像」的畫面規則

- 不新增虛擬角色、園子、果實、讀經排行榜或閱讀倍率。
- 不將經文筆記塞進靈修日誌，也不把靈修內容顯示成一般經文劃線。
- 不在經文頁預設顯示其他人的內容。
- 不因加入社群就改造現有首頁；先在聖經模組內驗證使用率。

## 五、分階段實作

### 階段 0：可維護原始碼與資料基礎

目前桌機與手機的現行生產介面已從編譯成品封存成可重建基準，但部分可讀前端原始碼曾遺失。正式改 UI 前必須：

1. 保留已驗證的生產基準與回滾包。
2. 先還原或重新建立「應用外殼、經文閱讀器、手機聖經頁」的可讀原始碼。
3. 每替換一個成品模組，都做畫面與路由對照，不直接編輯壓縮後的 JavaScript。
4. 修正 `scripture_selections` migration：補上 `version`、`offset_start`、`offset_end`、`updated_at` 與必要索引。
5. 為既有路由補上資料型別、經節範圍、字數及所有權測試。

完成門檻：桌機與手機均能從可讀原始碼建置；現有首頁、讀經、靈修與遊戲入口不退化。

### 階段 1：純經文工具（不需要外部 API）

1. 經文朗讀。
2. 使用裝置麥克風錄下自己的讀經聲音，在本機試聽、重錄或放棄。
3. 零 AI 的經文全文搜尋。
4. 劃線、私人筆記與書籤。
5. 繼續上次閱讀與章節位置記錄。
6. 複製經文與系統原生分享。

錄音由使用者按下按鈕後才要求麥克風權限；訪客錄音只存在當次裝置工作階段，不自動上傳。瀏覽器不支援錄音或使用者拒絕權限時，不影響其他讀經功能。

新增 API：

- `GET /api/content/scripture-search?q=&version=&book=&limit=&cursor=`
- `GET /api/scripture-reading-state`
- `PUT /api/scripture-reading-state`

搜尋直接查生產 `bible_verses`，使用現有 `pg_trgm`，不呼叫 LogosEngine、Gemini 或 FHL 即時 API。

完成門檻：搜尋結果逐字來自指定譯本；私人資料只能由本人存取；朗讀失效不影響閱讀；遊戲程式零變更。

### 階段 2：個人經文資料庫（仍非社群）

1. 「我的記錄」依書卷、日期、顏色與類型篩選。
2. 從筆記返回原譯本、原章節與原經節。
3. 登入會員可明確選擇把讀經錄音保存到自己的帳號；保存前先顯示檔案大小與隱私狀態。
4. 匯出自己的經文筆記。
5. 刪除與帳號資料管理；刪除錄音時同步刪除音檔及所有分享憑證。

這一階段不公開筆記或錄音、不建立追蹤關係，也不把私人筆記或聲音傳給 AI、免費模型或語音辨識服務。

### 階段 3：輕量分享與邀請制共讀

第一版社群只做「不公開、可撤銷」的分享：

1. 使用者選擇一段經文，建立未列出的分享連結。
2. 筆記預設不分享；必須逐次勾選才附加。
3. 使用者可把自己保存的朗讀錄音附在分享連結；聲音預設為私人，必須逐次確認才公開。
4. 分享頁清楚顯示譯本、出處、錄音長度與建立者自行填寫的文字；音訊不得自動播放。
5. 分享連結可設定期限並隨時撤銷。介面需說明：只要連結有效，取得連結的人就可能再次轉傳或保存音訊。
6. 建立邀請制「共讀小組」，只分享經文出處、短文字回應及使用者主動附加的朗讀。
7. 不提供公開動態牆、陌生人私訊、追蹤數、熱門排名或玩家全球位置。

預計新增：

- `scripture_share_links`
- `scripture_recordings`
- `scripture_recording_shares`
- `scripture_groups`
- `scripture_group_members`
- `scripture_group_posts`
- `scripture_group_reports`

必備治理：群組擁有者、成員移除、內容刪除、檢舉、封鎖、速率限制、審計紀錄與管理員處理入口。未完成治理前不開放公開社群。

### 讀經錄音的技術與隱私規則

- 錄製使用瀏覽器 `MediaRecorder`，不需要外部 API 或 AI tokens。
- 後端依瀏覽器實際支援格式接受音訊，驗證 MIME、檔案標頭、時長與大小，不相信前端副檔名。
- 第一版每段最多 5 分鐘、每檔最多 5 MB；每位會員另設總儲存上限，避免濫用。
- 音檔使用隨機內部名稱，不能從網址猜出使用者或經文。
- 本機預覽不自動上傳；按下「保存到我的記錄」後才傳到後端。
- 分享頁透過不可猜測且可撤銷的 token 取得音訊，不直接公開實體儲存路徑。
- 不做自動轉錄、聲紋辨識、AI 評分或發音評比。
- 不因錄音、被播放或被分享發放金幣，避免洗量與把讀經變成競賽。
- 初期可沿用生產主機的持久化上傳磁碟，但必須納入備份、容量監控與刪除流程；使用量成長後才評估 Cloudflare R2 等物件儲存。

預計新增 API：

- `POST /api/scripture-recordings`
- `GET /api/scripture-recordings`
- `GET /api/scripture-recordings/:id`
- `DELETE /api/scripture-recordings/:id`
- `POST /api/scripture-recordings/:id/share`
- `DELETE /api/scripture-recordings/:id/share/:shareId`
- `GET /api/public/scripture-recordings/:shareToken`

### 階段 4：附近教會轉介（獨立功能）

- 只在使用者主動要求或明確選擇時出現。
- 華人教會機構名錄 API Key 僅放後端。
- 後端只做代理、格式正規化與距離排序，不自行編造教會。
- 定位需即時同意；拒絕後可輸入城市或行政區。
- 位置預設不保存，不傳給教會，也不和讀經／社群紀錄綁定。
- 固定標示資料來源及「不代表本站背書」。

這一階段需要外部名錄 API；前四項經文工具均不依賴它。

## 六、不採用或延後的 VerseRain 概念

| 概念 | 判斷 |
|---|---|
| 經文朗讀 | 採用，但歸讀經工具，不進遊戲 |
| 錄下自己的讀經並分享 | 採用；先本機錄製與私人保存，之後才開未列出分享 |
| 換一節經文 | 可作搜尋／每日經文的次要功能，不取代現有每日靈修 |
| 經文搜尋 | 採用，先做本地全文搜尋 |
| 個人經文收藏 | 採用，改為低遊戲化的「我的記錄」 |
| 分享經文組 | 延後到個人記錄穩定後 |
| 邀請制共讀 | 可行，但必須有權限與治理 |
| 園子、種植、果實、互惠等級 | 不放入經文模組 |
| 經文排序挑戰、排行榜、PK | 若未來採用，只能另列遊戲功能，不納入本計畫 |
| 全球玩家地圖 | 不採用，避免隱私與產品定位偏移 |
| Google／LINE 登入 | 非本計畫必要條件，現有帳號可先沿用 |
| 每日推播 | 延後；需要 Service Worker、通知權限與獨立退訂治理 |

## 七、驗收條件

- 現有桌機與手機讀經路徑、譯本、章節切換及對照功能不退化。
- 經文正文只來自生產正式經文庫；朗讀、分享與搜尋不得偷偷替換譯本。
- `scripture_selections` 的程式與生產 schema 完全一致，新增／更新／刪除均通過所有權測試。
- 經文搜尋不呼叫 AI，查詢結果具譯本、書卷、章、節與命中文字。
- 朗讀不需要金鑰；瀏覽器不支援時顯示清楚訊息，不阻止閱讀。
- 麥克風只在使用者操作後要求權限；拒絕、錄音失敗或上傳失敗均不影響經文閱讀。
- 未按下保存前，錄音不得傳送到後端；未按下分享前，私人錄音不得由公開端點取得。
- 錄音刪除或分享撤銷後，原分享 token 立即失效且無孤兒音檔。
- 私人筆記預設不分享；建立分享連結前明確預覽實際會公開的內容。
- 已撤銷或過期分享連結無法再取回內容。
- 未加入小組者無法讀取小組內容；他人的資源一律回 404。
- 社群功能不改動遊戲題庫、選題、難度、金幣或排行榜。
- 附近教會 API 失效時不生成替代名單，定位資料不落庫。
- 每一階段有獨立功能開關、migration、測試、部署包與回滾方式。

## 八、建議執行順序

先完成階段 0，再只做階段 1。階段 1 實際使用穩定後，才決定是否需要個人資料庫、分享或共讀。

這個順序的目的不是把功能做少，而是先讓「讀經本身更好用」，再觀察使用者是否真的需要社群；如此可避免經文、靈修、遊戲與社群同時堆在首頁而失去產品重心。
